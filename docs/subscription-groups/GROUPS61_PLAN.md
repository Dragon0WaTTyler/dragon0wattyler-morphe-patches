# groups.6.1 concrete plan and native-menu boundary

Continue the verified V6 source in a separate directory; preserve V1–V6 distributions and exact build dependencies. Target remains21.30.216/API29+; no matching stock APK/device is currently available.

## Evidence and root cause

V6 GroupVideoActions owns an Android PopupMenu (not the real YouTube sheet). Its GroupVideo model carries public-feed identity/presentation only, without native MenuRenderer, opaque service/feedback commands, command executor, interaction logger or sender context. FeedVideoActionsPatch opens a bound native view's menu by performClick; it does not build an arbitrary video menu. FlyoutPatch extracts context from a native command's Map. AskFlyoutMenuPatch demonstrates native Elements tap-handler command getters and invocation, and native sheet/popup row dispatch. QueueFlyoutActions changes existing native models and preserves native dispatch; its account/queue-specific synthetic rows are not a general feed menu. Reusing native card rendering would require a native renderer/model/resources plus its binding context, absent from current RSS/public web metadata. No safe generic constructor is exposed in these source hooks.

## Implementation

1. Add an unnamed internal patch using the already-existing ElementsTapHandler fingerprints. Add uniquely named getters to serialize the original native command and invoke the original tap handler with the actual group button as sender. Capture at the native handler constructor's normal returns. Do not replace native menu models, intercept native row actions or force-enable Ask/queue patches. Preserve original native Home execution paths.
2. Recognize only real native commands containing the existing MenuRenderer extension66439850. Decode explicit video-targeted endpoints using the repository's native protobuf schema, reject mixed/ambiguous/missing IDs and malformed/oversized/deep inputs. Never replace IDs, clone another video's menu, fabricate commands/icons or serialize a custom action list into a native-looking sheet.
3. Retain a bounded, short-lived weak registry of original handlers, scoped to the active host activity and monotonically changing account-context generation. Validate the complete original command bytes again immediately before invocation. Reject expired/rebound/collected/other-account/incognito/other-activity handlers. Do not persist commands, native context or account data. Keep native action availability and handlers entirely owned by YouTube/Morphe.
4. On group ⋮, try that exact captured native handler. If missing or rejected, show the small existing functional fallback, without claiming it is native. Keep local watched/unwatched and Play/Open channel/Share accessible by long-pressing ⋮ even when the native menu succeeds. Add a localized accessibility hint. No manual imitation of the full stock action list.
5. Add tests for actual native-command identity parsing, correct bridge invocation/sender, original byte preservation, account/lifecycle invalidation, command rebinding, rapid/reordered selection, video types, supported fallback/local watched preservation and no mutation of unrelated native paths. Add synthetic DEX tests for bridge register/parameter/return safety and coexistence with existing Ask hooks. Run full V6 regression suites, string checks, then documented buildAndroid; verify DEX and194 existing upstream declarations.
6. Package2.0.0-groups.6.1 MPP, complete four-repository source, focused diff, real test report, exact compatibility limits and focused Samsung instructions. Preserve rollback checksums. No target-device native-menu success claim without testing.

## Explicit remaining limitation

This route can reuse only native menu commands that YouTube has actually bound for that same video in this activity/session. It cannot manufacture native menu context for every RSS-only video. A video ID and public web JSON do not supply account/context-specific native feedback commands. Missing bindings use the limited functional fallback. Full arbitrary-card native-menu coverage and exact target fingerprint/runtime behavior remain unverified; do not label the candidate full native-menu integration. No undocumented PocketTube API, Drive access, account/Premium bypass or proprietary extension code is involved.
